## 交付内容

ZIP 是源码打包文件，SHA-256 是根据内容生成的文件指纹。

| 内容 | 已完成的工作 |
|---|---|
| tools/build_release.py | 按 ship.json 选择源码，固定文件顺序、时间戳与权限，生成 ZIP、SHA-256 和发行清单 |
| tools/check_release.py | 实测许可原文、README 七节、锁定依赖、禁止的产物、被追踪文件大小、版本来源、个人路径与待填项 |
| THIRD_PARTY.md | 从已有环境的依赖元数据显式生成，之后作为源码冻结；打包过程不读取本机依赖元数据 |
| requirements-release.lock | 记录既有运行依赖、其本地依赖链和构建后端的精确版本；没有安装依赖 |
| docs/judges/ | 英文评委入口、安装运行、架构草稿、新增 Kit、验证限制、构建与新环境验证步骤 |
| tools/clean_env_verify.py | 默认只输出计划；显式执行分支准备了新环境安装、安装位置检查、示例运行、封存包复验与逐条输出保存 |
| examples/run_example.py | 经公开命令运行独立手算的反向互补示例；区分源码执行与安装包执行 |
| examples/sealed/b1/ | 本轮实际产生并复验的便携合成示例；保留真实的 dev-tree 开发标记 |

发行身份是发行清单内容的摘要，区别于整个 ZIP 的摘要。清单列出版本、构建标识、
文件路径/大小/哈希及依赖，不包含自身文件条目或自身摘要。ZIP 不包含依赖二进制。
唯一版本文件仍是 VERSIONS.json；打包时只生成其安装资源副本，没有修改版本源。
