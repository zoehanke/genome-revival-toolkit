## A：直接文件交接

原行为：Construct 的交接文件引用两个 GenBank 文件，但交付清单没有它们；
Identity 模板只读 FASTA，而且要求额外引物文件。Evidence 的既有预测文件端口
也没有现成模板绑定。违反 D11 的前一步交付文件直接进入后一步的要求。

泛化依据：D11 已含文件哈希、参考角色和引物序列，不需要改变交接形状。
文件读取复用 Core 现有格式解析器，不增加 PCR 算法或生物学假设。

改动：

* Construct 的同一交接步骤额外交付两个参考原字节副本，均属于交接分析材料。
  两个现有制备模板都交付它们，仍绑定原有交接目标，不增加目标参数。
* Identity 的 `read_reference` 适配器复用既有参考解码/哈希绑定路径，支持
  FASTA、GenBank、原生 DNA。参考仍进入原有材料步骤与 Core 检查。
  `from_handoff` 从交接文件中选择用户明确给出的两个引物 id，不制作引物文件。
  显式给出的冲突引物仍失败；只给一条、缺 id、错哈希、未知格式均不猜测。
  `from_references` 及其科学预期保持原样。
* Evidence 新模板 `assess_predictions` 绑定已经存在的可选预测文件端口。
  观察数据专用的原模板与计算不变。未引入新模式、状态词、事件或关系类型。
