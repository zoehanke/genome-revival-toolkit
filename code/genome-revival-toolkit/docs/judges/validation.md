# Validation results and limits

S4a evidence is developer-run engineering evidence. Its release tests construct
valid and invalid source trees, execute each release check, build the same tree
twice and inspect actual archive membership, timestamps and hashes. A prohibited
extension, wrong license, missing README section, unpinned requirement, oversized
tracked tree, wrong version source or unfinished disclosure must not pass.

The retained B1 example computes AGTCAGAA to the independent hand answer TTCTGACT,
then checks and seals the report. A portable copy is verified after the original
run location is unavailable. It contains no user DNA and demonstrates no Kit or
wet-laboratory behavior. Its development-tree release identity is retained.
